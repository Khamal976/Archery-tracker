# Трекинг тренировок по стрельбе из лука

Локальное веб-приложение: на телефоне вносишь попадания прямо на рубеже, на десктопе
разбираешь статистику и сравниваешь настройки снаряжения. Работает офлайн, ставится как PWA.
Бэкенда, аккаунтов, облака, аналитики и сетевых запросов нет — данные лежат только в браузере,
в IndexedDB. Перенос между устройствами — экспортом и импортом файла.

## Запуск

Первый раз — установить зависимости:

```bash
npm install
```

Дальше каждый раз:

```bash
npm run dev
```

Открыть http://localhost:5173. Команды даны по одной: в Windows PowerShell 5.1 склейка
через `&&` не работает — если хочется одной строкой, там это `npm install; npm run dev`.

Остальные команды:

```bash
npm run build
```

```bash
npm test
```

```bash
npm run icons
```

`npm run icons` перерисовывает иконки PWA (`public/icon-*.png`, `favicon.svg`) — они
генерируются кодом, а не лежат бинарниками.

## Установка на Android

Приложение — статика без бэкенда, поэтому «установить» его значит открыть страницу в Chrome
и добавить на домашний экран. Есть одно жёсткое условие: **service worker живёт только в
защищённом контексте** — это `https://` или `localhost`. По локальному IP вида
`http://192.168.1.5:5173` приложение откроется и будет работать, но офлайна и установки
не будет.

### Быстро посмотреть с телефона (без установки и офлайна)

```bash
npm run dev -- --host
```

Vite напечатает адрес в локальной сети — открыть его в Chrome на телефоне. Ноутбук и телефон
должны быть в одной сети; Windows может спросить разрешение брандмауэра.

### Поставить по-настоящему, вариант 1: кабель и ADB

Самый надёжный способ: адрес `localhost` не меняется никогда. Если `adb` ещё нет, поставить
Android SDK Platform-Tools — это ~10 МБ, Android Studio не нужна:

```bash
winget install --id Google.PlatformTools
```

Включить на телефоне отладку по USB, подключить кабель, принять запрос авторизации и:

```bash
adb reverse tcp:4173 tcp:4173
```

Дальше `npm run build`, `npm run preview -- --port 4173`, и на телефоне открыть
`http://localhost:4173`. Для Chrome это защищённый контекст, поэтому появится пункт меню
«Установить приложение». После установки всё лежит в кэше и работает без компьютера и без
сети. Кабель нужен снова только чтобы обновить версию.

### Вариант 2: без кабеля, через флаг Chrome

Ставить нечего, но приложение окажется привязано к адресу ноутбука в локальной сети.

Собрать и поднять раздачу по сети:

```bash
npm run build
```

```bash
npm run preview -- --host --port 4173
```

На телефоне открыть `chrome://flags/#unsafely-treat-insecure-origin-as-secure`, вписать туда
адрес вида `http://192.168.1.5:4173`, включить, перезапустить Chrome. Теперь этот адрес для
Chrome защищённый: service worker зарегистрируется, появится «Установить приложение».

Подвох: origin установленного приложения — это тот самый `IP:порт`. Если роутер выдаст
ноутбуку другой адрес, установленное приложение будет открываться из кэша, но перестанет
обновляться. Лечится статическим адресом в настройках роутера или переходом на вариант 1.

### Вариант 3: статический хостинг (используется сейчас)

Приложение живёт на Cloudflare Pages. Автономность от этого не страдает: после установки оно
не делает ни одного сетевого запроса, данные остаются в браузере телефона.

Выкладка идёт через официальный CLI, панель Cloudflare для этого не нужна:

```bash
npm run build
```

```bash
npm run deploy
```

При первом запуске `wrangler` откроет браузер и попросит авторизовать доступ к аккаунту
Cloudflare — это разовое действие. Имя проекта зашито в скрипт `deploy` в `package.json`.

Тот же путь через панель, если CLI по каким-то причинам не годится: **Workers & Pages →
Create → вкладка Pages → Upload assets**, перетащить содержимое `dist`. В новой панели
вкладка Pages неочевидна, потому что интерфейс подталкивает к Workers; прямая ссылка —
`dash.cloudflare.com/?to=/:account/pages/new/upload`.

Годится и любой другой хостинг статики с HTTPS — Netlify, Vercel, GitHub Pages.

Если хостинг отдаёт приложение из подпапки (типичный случай GitHub Pages), собирать нужно
с указанием базового пути, иначе не найдутся ни ассеты, ни service worker:

```bash
$env:BASE_PATH='/имя-репозитория/'; npm run build
```

### После установки

Chrome на Android обычно молча выдаёт постоянное хранилище установленному приложению —
статус видно в настройках приложения внизу. Вибро таймера работает, экран не гаснет во время
сессии. Обновление приложения прилетает само при следующем запуске с сетью: service worker
собран в режиме `autoUpdate`.

## Модель данных

```
сессия → этапы → серии → выстрелы
```

- **Сессия** — одна тренировка или один раунд. Ссылается на формат, место, заметку перед
  стартом, разбор после и на **конкретную версию сетапа**, а не на сетап целиком.
  Завершить можно любую сессию в любой момент — статистика сохранится, а недобитый
  стандартный формат просто не пойдёт в рекорды.
- **Этап** — дистанция + фейс + число серий + стрел в серии. Простые форматы (WA 18 м,
  WA 70 м) — один этап; FITA 900 и FITA 1440 — несколько этапов с разными дистанциями.
- **Серия** — один подход. У серии свой режим ввода: по мишени или числами.
- **Выстрел** — координаты в миллиметрах, индекс спота, номинал, флаги X, промаха и
  повторного спота.

Все mrad-метрики считаются по дистанции своего этапа. Идентификаторы — UUID, у каждой
сущности есть `updatedAt`; удаление мягкое (`deletedAt`), тумбстоуны едут в бэкапе, иначе
удалённая на одном устройстве сессия воскресала бы при импорте с другого.

## Конвенция координат

**+x вправо, +y вверх, с точки зрения стрелка, смотрящего на мишень.** Единица — миллиметр.
Начало координат — центр фейса, а для многоспотовых фейсов — **центр своего спота**
(поэтому споты складываются в одну группу и кучность считается корректно).

Конвенция одна и та же в хранении, метриках, CSV и подсказке по прицелу. SVG рисует y вниз;
перевод живёт ровно в одном месте — `src/core/viewbox.ts`.

Диаметр стрелы при определении кольца не учитывается: точка тапа — это точка. Попадание
точно на линию кольца засчитывается в пользу большего номинала.

## Что где лежит

| Путь | Что там |
| --- | --- |
| `src/core/` | Чистая математика без React и Dexie: фейсы, счёт, метрики, форматы, поля сетапов, справочник по настройке |
| `src/db/` | Схема Dexie и операции над данными |
| `src/lib/` | Агрегация статистики, экспорт/импорт, таймер, wake lock |
| `src/ui/` | Мишень в SVG, тепловая карта, блоки метрик, атомы интерфейса |
| `src/screens/` | Экраны |

Тесты лежат рядом с кодом (`*.test.ts`) и покрывают только математику — граничные случаи
счёта, метрики, мерж бэкапа.

## Принятые решения по формулам

Эти вещи в ТЗ были заданы не до конца; выбор зафиксирован здесь, чтобы результаты были
воспроизводимы.

- **Порог данных.** Метрики кучности считаются от n ≥ 3 выстрелов с координатами. Меньше —
  пометка «мало данных», нулей не подставляем. Серии, введённые числами, координат не имеют
  и в кучность не идут вовсе.
- **CEP** — эмпирический перцентиль расстояний от центроида с линейной интерполяцией
  (тип 7, как в numpy и Excel `PERCENTILE`). Рэлеевская оценка не реализована сознательно:
  она предполагает круговую нормальность и врёт на вытянутых группах. При n < 10 CEP95
  подписывается «ориентировочно»; на трёх точках он почти упирается в максимум.
- **Флаер** — выстрел дальше 2.5 радиальных СКО от центроида, где центроид и СКО считаются
  **по остальным выстрелам**. Без этого одинокий далёкий выстрел раздувает СКО настолько, что
  сам под порог не попадает, и на серии из шести стрел правило не срабатывает никогда.
  Проход один, итеративного пересчёта нет. Флаеры ищутся по этапу целиком (n меньше пяти —
  пометок нет), чтобы на разных уровнях статистики они не противоречили друг другу.
  Исключение флаеров меняет только кучность и смещение — счёт, средний балл и рекорды
  не трогает никогда.
- **Значимость смещения** для подсказки по прицелу — по каждой оси независимо:
  |среднее| > 2 · СКО / √n. Поэтому подсказка бывает только по вертикали. Прицел двигается
  **вслед за группой**.
- **Сессия целиком** при нескольких этапах считается в mrad: точки переводятся по дистанции
  своего этапа. Миллиметры между дистанциями не смешиваются — на многоэтапной сессии их
  просто нет.
- **Спот-зона.** Тап дальше радиуса зоны спота — промах. Между внешним кольцом и краем зоны
  тоже промах, но с координатами: он участвует в кучности, а не выпадает из неё.
- **Внутренняя десятка.** На фейсе с флагом «только внутренняя десятка» внешняя десятка даёт
  9, внутренняя — 10 и увеличивает счётчик X (X — тай-брейк в рекордах).
- **Полнота сессии.** Этапы без ограничения по сериям неполноты не создают. В личные рекорды
  идут только завершённые полные сессии стандартных форматов.
- **Отстрел без счёта** не участвует в среднем балле — ни в графике по сессиям, ни в сравнении
  сетапов, ни в рекордах: баллов там нет, и нулём их подменять нельзя. В кучность, тепловую
  карту и объём тренировок он входит полностью.
- **Часы объёма** — сумма активного времени сессии; пауза не считается. Время копится, пока
  открыт экран ввода.
- **Мерж импорта** — last-write-wins по `updatedAt`; при равенстве остаётся локальная запись,
  поэтому повторный импорт одного и того же файла ничего не меняет.

## Мишени

Фейс — это данные: габариты, кольца с радиусами и номиналами, флаг X, флаг «только
внутренняя десятка», геометрия спотов, шаг сетки для пустого поля. Новый фейс заводится из
интерфейса (Настройки → Мишени), правка кода не нужна. Из коробки: WA 122, 80, 60, 40,
трёхспот 40 вертикальный и треугольный, компаунд 40 и компаунд 80 (6 колец), пустые поля
40, 60 и 80 см для blank bale.

Кольца рисуются каноническими цветами WA, но приглушёнными: чистого белого и яркого голубого
в приложении нет нигде — на солнце они слепят.

## Справочник по настройке

Раздел «Настройка лука» (`/tuning`) — личный конспект владельца: центровка плечей, база,
тиллер, насечки на тетиве, посадка хвостовика, центр-шот, планжер и метод отхода. Лежит
данными в [`src/core/tuning.ts`](src/core/tuning.ts), правится там же.

Разделы привязаны к группам полей сетапа: в карточке снаряжения над группой «Плечи» стоят
ссылки на «Центровку плечей» и «Тиллер», над «Тетивой» — на «Базу», «Насечки» и «Посадку
хвостовика», над «Плунжером» — на «Центр-шот» и «Планжер».

Иллюстрации лежат в `public/tuning/` и готовятся из исходного PDF скриптом:

```bash
node scripts/tuning-images.mjs "C:/путь/Настройка рекурсивного лука.pdf"
```

Скрипт вытаскивает JPEG-потоки прямо из PDF, отбирает нужные по `MANIFEST` и ужимает их
до 1000 px и качества 68 — оригиналы весят 3.5 МБ, а всё содержимое уходит в офлайн-кэш.
В `MANIFEST` попали только собственные фотографии и рисунки автора; превью чужих роликов
из документа сознательно не переносятся. Единственная нарисованная кодом схема —
картина попаданий при методе отхода в [`TuningFigures.tsx`](src/ui/TuningFigures.tsx).

## Экран блокировки и батарея

Показать страницу поверх экрана блокировки телефона веб-приложение не может — это флаг
нативной Activity. Поэтому телефон просто не блокируется, пока идёт сессия
(Screen Wake Lock), а картинку гасит собственный дежурный слой: почти чёрный экран с текущим
счётом, тап по нему возвращает ввод без разблокировки. Wake lock снимается на паузе и при
выходе с экрана ввода; в режиме энергосбережения Chrome может отказать — это не ошибка,
состояние сессии всё равно пишется в базу после каждого выстрела.

Вибро таймера работает на Android. На iOS `navigator.vibrate` не поддерживается — там
останутся звук и визуальный отсчёт.

## Живучесть данных

При первом запуске приложение просит `navigator.storage.persist()`, чтобы браузер не выселил
IndexedDB. Если последнего экспорта не было дольше 14 дней, на главной появляется
ненавязчивое напоминание про бэкап — без модалок и без блокировки работы. Фактический статус
хранилища виден в настройках.

Полный бэкап — JSON со всеми сессиями, этапами, сериями, выстрелами, сетапами со всеми
версиями, кастомными фейсами и настройками. CSV — плоская таблица выстрелов для Excel
(разделитель `;`, десятичная запятая, BOM), только на выгрузку.
